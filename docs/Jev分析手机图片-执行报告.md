# 用 Jev 从手机相册批量筛简历实测报告

## 一、核心结论（结论先行）

> **一句话总结**：用 `jev-1.14.0` 的 `noul`（单题二元打分）批量粗筛手机非相机相册 **3,608 张**图片，**耗时 8.8 分钟、总成本约 $0.49**，以极高区分度筛出 **32 张**疑似简历（占成功样本 **0.90%**），适合作为「先粗筛、后精读」的轻量前置漏斗。

### 关键结论

1. **极低成本粗筛**：按输入 token 计费（$0.042 / 百万输入 token，输出免费），平均每张图约 **3,257 input tokens**、单张均价 **$0.00014**（约 **$0.14 / 千张**），比直接上强多模态模型或全量 OCR 便宜 1–2 个数量级。
2. **打分区分度极强（双峰分布）**：3,564 张成功样本中，**98.71%（3,518 张）分数低于 0.2**，高置信疑似（`≥ 0.9`）集中为 **25 张**，灰区（`0.5–0.7`）仅 **8 张**，几乎不需要复杂调参。
3. **先按相册过滤收益巨大**：排除生活实拍为主的 `Camera`（3,778 张）直接省掉一半成本；剩余队列中，命中集中在 `DCIM`（6.67%）、`面经`（8.70%）和 `WeiXin`（1.52%），而占比 67% 的 `Screenshots`（2,401 张）命中率仅 **0.12%**。
4. **耗时瓶颈在并发度与 API 往返，不在本地预处理**：单张全链路均值 **1.186s**，其中 Jev API 延迟占 **1.012s（85.3%）**，ADB 拉图与本地缩放仅占 **0.174s（14.7%）**。本次 8 并发跑出 **6.87 QPS**，远低于官方限额，拉高并发即可线性提速。
5. **需要补网络重试**：44 次失败（1.2%）中 **63.6%（28 次）是可恢复的瞬态连接错误**（连接被拒 / SSL 中断 / 超时），加 1–2 次重试即可将有效成功率推到 99.5% 以上。

## 二、实验设置与处理链路

| 项 | 配置 |
|---|---|
| 模型与接口 | `jev-1.14.0`（System One 决策 API，`POST /v1/systemone`，图片实验头 `TypeSafe-Danger-Zone-Images: true`） |
| 判断题型 | 单题 `noul` 打分（`is_resume`：仅判断是否为含工作/教育/技能/个人信息的简历，排除普通截图、面经题、聊天记录等） |
| 判定阈值 | `noul ≥ 0.7` 记为疑似简历 |
| 样本范围 | Android MediaStore 共 **7,386** 张；排除 `Camera` 相册 **3,778** 张，实测队列 **3,608** 张 |
| 图片预处理 | EXIF 转正 → 统一转 JPEG → 约束边长在 280–1568 px、单文件 ≤ 15 MiB（超长截图会等比压扁，够粗筛用） |
| 并发度 | 8 |

> 设计取舍：每张图只打一道 `is_resume` 单标，避免多题并行互相干扰导致 `noul` 阈值失效。

## 三、执行情况与效果分析

### 3.1 总体吞吐与耗时拆解

| 指标 | 实测值 | 说明 |
|---|---|---|
| 队列 / 成功 / 失败 | 3,608 / 3,564 / 44 | 成功率 **98.8%** |
| 疑似简历（`≥ 0.7`） | **32 张** | 占成功样本 **0.90%** |
| 墙钟总耗时 | **525.5 s**（约 **8.8 min**） | 含无线 ADB 拉图与本地预处理 |
| 有效吞吐 | **6.87 QPS** | 并发 8 |
| 单张全链路耗时 | 均值 **1.186 s**（P50 **1.055 s**） | ADB 拉取 + 缩放转码均值仅 **0.174 s**（14.7%） |
| Jev API 延迟 | 均值 **1.012 s**（P50 **0.874 s** / P95 **1.819 s** / Max **4.299 s**） | 占单张耗时 **85.3%** |

### 3.2 `noul` 分数分布（3,564 张成功样本）

| 分数区间 | 张数 | 占比 | 判定含义 |
|---|---:|---:|---|
| `≥ 0.9` | 25 | 0.70% | 高置信简历 |
| `0.7 – 0.9` | 7 | 0.20% | 过阈值疑似，需人工复核 |
| `0.5 – 0.7` | 8 | 0.22% | 灰区（未计入疑似，可按需抽看） |
| `0.2 – 0.5` | 6 | 0.17% | 偏不像 |
| `0.0 – 0.2` | 3,518 | 98.71% | 明确负例 |

正负例之间隔着极宽的空白带（`0.2–0.7` 合计仅 14 张，占 0.39%），`noul` 单标区分度非常干净。

## 四、成本与扩容估算

| 指标 | 实测值 |
|---|---:|
| 输入 token | 11,606,758（约 11.61M） |
| 输出 token | 74,844（免费） |
| 总费用估算（$0.042 / 1M 输入 token） | **≈ $0.487** |
| 成功单张均值 | **≈ 3,257 input tokens / $0.00014** |

按当前口径外推：
- **每千张图片**：约 **$0.14**；即使覆盖全库（含 Camera 7,386 张）总成本也仅 **$1.0 左右**。
- **提速空间**：官方默认限额约 80 RPS / 100k TPS，本轮仅用 8 并发跑出 6.87 QPS；若把并发拉到 24–32 并配合网络重试，3,600 张规模预计可压进 **2–3 分钟**内完成。

## 五、工程实践建议

1. **先粗筛后精读**：先用单题 `noul` 以 ~0.14 美元/千张的成本把几千张图收敛到几十张候选，再交给 OCR 或强多模态模型做字段提取，成本与耗时可降两个数量级。
2. **按相册优先级分批扫**：`Screenshots` 占了 67% 的 token 消耗却只产出 3 张候选；若只求找回简历，优先扫 `DCIM`、`WeiXin` 与求职专项相册即可覆盖主体并再省约 2/3 成本。
3. **补齐重试与超长图裁切**：并发调用务必加 2 次瞬态网络重试；粗筛命中的超长截图在进入精读前建议按原图分页裁切，避免压扁后小字识别失真。

## 六、附录：无线 ADB 取图命令

```bash
# 1. 配对 + 连接（手机「无线调试 → 使用配对码配对」；配对端口 ≠ 连接端口）
adb pair <手机IP>:<配对端口>
adb connect <手机IP>:<连接端口>
adb devices

# 2. 列出相册图片（MediaStore；注意列名为 _display_name 而非 display_name）
adb -s <手机IP>:<连接端口> shell 'content query --uri content://media/external/images/media --projection _id:_data:_display_name:bucket_display_name:date_added --sort "date_added DESC"'

# 3. 拉取单张图片
adb -s <手机IP>:<连接端口> pull /storage/emulated/0/.../xxx.jpg ./local.jpg
```

批跑阶段即对步骤 2 过滤掉 `Camera` 后的列表并发执行「`adb pull` → 本地缩放转 JPEG → 调 `POST /v1/systemone`」。
